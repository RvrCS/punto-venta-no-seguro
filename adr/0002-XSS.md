# ADR-0002 · Codificación de salida en el controlador de reportes

- **Estado:** Aceptado
- **Fecha:** 2026-11-17
- **Autor(es):** Pablo Emilio Zamora Gamez
- **Hallazgos relacionados:** XSS-02

## Contexto

El endpoint de exportación de reportes en formato HTML (ReporteControlador.java) acepta parámetros de entrada controlados por el usuario, específicamente nombreCliente.

```java
@GetMapping(value = "/exportar/html", produces = MediaType.TEXT_HTML_VALUE)
public String exportarHtml(@RequestParam(required = false) String nombreCliente, @RequestParam(defaultValue = "COMPLETADA") String estado) {
    return servicio.exportarHtml(nombreCliente, estado);
}
```

La aplicación concatenaba este parámetro directamente dentro de la estructura del documento HTML retornado con el tipo de contenido text/html. Como consecuencia, un atacante podía inyectar payloads maliciosos mediante etiquetas ejecutables (por ejemplo, ?nombreCliente=<script>alert('XSS-Reportes')</script>), los cuales se reflejaban textualmente en la respuesta y se ejecutaban de inmediato en el contexto del navegador del usuario. Esto exponía credenciales, cookies de sesión y permitía la manipulación visual de la interfaz.

## Decisión

Se implementa una estrategia estricta de codificación de salida (Output Encoding) utilizando la utilidad nativa de Spring Framework `HtmlUtils.htmlEscape()` en el controlador antes de procesar o retornar el valor hacia la capa de servicio:

```java
String clienteSeguro = (nombreCliente != null) ? HtmlUtils.htmlEscape(nombreCliente) : "General";
return servicio.exportarHtml(clienteSeguro, estado);
```

- **Mitigación en el punto de salida:** Los caracteres especiales susceptibles de interpretarse como código HTML/JavaScript `(como <, >, ", ')` se transforman en sus respectivas entidades HTML seguras `(&lt;, &gt;, etc.)`.
- **Preservación del negocio:** El sistema continúa generando los reportes en HTML con normalidad, manteniendo intacto el flujo de consultas de los operadores y cajeros.

## Alternativas consideradas

| Opción | Pros | Contras |
|---|---|---|
| Dejarlo como está y confiar en el frontend | Sin cambios | Inseguro; el endpoint puede invocarse directamente mediante herramientas de red (curl, Postman) ignorando las restricciones visuales del cliente. |
| Validación por Expresiones Regulares (Whitelist/Blacklist)| Filtrado estricto de caracteres | Propenso a errores de diseño, bypass mediante codificaciones alternativas y mantenimiento complejo ante entradas de texto legítimas complejas. |
| Migrar a un motor de plantillas pesado `Thymeleaf/FreeMarker`| Separación nativa de la vista | Alto costo en tiempo de desarrollo y refactorización para un endpoint puntual de exportación directa. |
| **Codificación de salida explícita con HtmlUtils.htmlEscape() (Elegida)** | Bajo impacto, nativa de Spring, rápida y segura en el punto de inyección | Requiere asegurar que cada parámetro reflejado pase por el método de escape.|

## Consecuencias

- **Positivas:**
  - Neutralización total del vector de Inyección de Scripts Reflejados (XSS-02) en el módulo de reportes.
  - El navegador del usuario procesa los caracteres inyectados de forma inocua como texto plano y no como código ejecutable.
  - Se mantiene la integridad visual y la seguridad de las sesiones de los administradores y operadores del POS.
- **Negativas / costos:**
  - Los usuarios que legítimamente posean caracteres especiales (como símbolos matemáticos o etiquetas en los nombres de clientes) los visualizarán como entidades HTML literales a menos que se implemente un renderizado adaptado en la vista.
- **Prueba que demuestra el control:** 
- `backend/src/test/java/com/curso/pv/config/XssTest.java` Prueba unitaria de integración mediante @WebMvcTest y MockMvc):
  - Envía un payload malicioso `<script>alert('XSS-Reportes')</script>`.
  - Valida que la respuesta HTTP contenga exclusivamente la versión escapada `&lt;script&gt;` y comprueba que la etiqueta cruda de ejecución no esté presente `not(containsString("<script>"))`.

  Resultado:

  | Versión de `ReporteControlador` | Resultado |
  |---|---|
  | Original (`Sin fix`) | 🔴 `Tests run: 3, Failures: 1` Fallaba al encontrar el script ejecutable sin alterar en el cuerpo de la respuesta. |
  | Con el fix | 🟢 `Tests run: 3, Failures: 0` |

  Comando: `cd backend && mvn test -Dtest=XssTest`
